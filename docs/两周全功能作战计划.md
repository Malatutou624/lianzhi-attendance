# 两周全功能作战计划（2 人 · 零基础 · AI 全程协助）

> 军规：每天的功能**当天必须跑通**再睡觉；卡住超过 2 小时立刻问 AI 或降级方案。

## 角色（两人都要懂全链路，只是主攻方向不同）

- **A（后端主导）**：Java / SpringBoot / MySQL / 虹软 SDK
- **B（前端主导）**：Vue / ElementPlus / H5 / ECharts

## 第 1 周：骨架 + 主链路前半段

| 天 | A 的任务 | B 的任务 | 当天验收标准 |
|---|---|---|---|
| D1 | 装齐环境（JDK/IDEA/MySQL/Redis）；跑通后端骨架；**注册虹软开发者账号并申请 SDK**（审核要时间，第一天就申请！） | 装 Node；跑通前端骨架；熟悉 Vue 基础语法 | 两人电脑都能打开登录页并登录成功 |
| D2 | 读懂骨架代码（让 AI 逐行讲）；场所模块跑通 | 读懂前端骨架；场所管理页跑通 | 场所能增删改查 |
| D3 | 地图坐标采集接入（高德地图 JS API，免费 key） | 场所表单加地图选点组件 | 点地图自动填经纬度 |
| D4 | 二维码生成接口打磨；理解 zxing 原理 | 场所页"生成场所码"按钮 + 二维码弹窗 + 下载 | 扫码能解析出场所参数 |
| D5 | 员工接口完善 + 照片上传 | **H5 采集页**（独立 uni-app 工程，HBuilderX 打开）：填信息+拍照上传 | 手机扫码打开 H5，提交后管理端员工列表可见 |
| D6-7（周末） | 复习本周代码 + 互相讲数据流；补掉队内容 | 同左 | 能给对方讲清"登记→二维码→采集"全链路 |

## 第 2 周：人脸识别 + 看板 + 加分项 + 部署答辩

| 天 | A 的任务 | B 的任务 | 当天验收标准 |
|---|---|---|---|
| D8 | **虹软 SDK 接入**：员工采集时提取人脸特征值存库 | H5 打卡页：调摄像头拍照、带 venueId 提交 | 员工注册时 face_feature 入库 |
| D9 | **人脸比对打卡接口**：比对相似度→写打卡记录→按规则判迟到；Redis 防 5 分钟内重复打卡 | H5 打卡页联调：成功/失败提示 | 手机刷脸打卡，记录列表实时可见 |
| D10 | 活体检测接入（虹软活体接口）；人证核验（身份证+人脸比对） | H5 打卡流程完善 | 用照片骗打卡被拦截 |
| D11 | Spring Task：每天凌晨统计写入 daily_stats；统计接口 | **数据看板**：今日概览卡片 + 打卡趋势折线图 + 部门分布饼图 | 看板展示真实数据 |
| D12 | 场所热力图接口（按经纬度聚合打卡点）；近期趋势接口 | ECharts 地图/热力图 + 趋势折线图 | 看板 4 种图齐全 |
| D13 | 请假/加班申请审批接口 | 请假申请页 + 审批页；uni-app 编译微信小程序试跑 | 申请→审批流转通 |
| D14 | Docker 打包（有时间就做，没时间本地跑通即可）；整体联调修 bug | 全功能测试清单逐条过；验收 PPT | 全链路演示一遍不卡壳 |
